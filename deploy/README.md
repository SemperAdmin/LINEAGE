# Deploying LINEAGE to cloud.gov

Target: `lineage.app.cloud.gov`, app name `lineage`, staticfile buildpack.

## Deploy

Run from this directory. One command per line, Windows PowerShell 5.1 has no `&&`.

```powershell
cd D:\Coding\LINEAGE\deploy
python prepare.py
cf login -a api.fr.cloud.gov --sso
cf target -o <ORG> -s <SPACE>
cf push
```

`cf orgs` and `cf spaces` list what you have access to if you do not know the names. `cf push` reads `manifest.yml` from the working directory.

Confirm the deploy:

```powershell
cf app lineage
curl.exe -I https://lineage.app.cloud.gov/
```

The response must carry a `Content-Security-Policy` header. If it does not, `location_include` did not take effect and the guarantee below is not being enforced.

## What prepare.py is for

It copies `../index.html` into `public/` and **refuses to stage a file whose SHA-256 does not match the published build**.

Someone who downloads the tool can hash it. Someone who loads it from a URL cannot, because they never hold the bytes. This script is the last point at which anyone checks, so it checks.

If you change `index.html`, re-run the acceptance suite, publish the new digest in `README.md` and in `docs/VERIFICATION_RECORD_2026-08-24.md`, and update `EXPECTED` in `prepare.py`. All four move together or none do.

## What the nginx config is for

LINEAGE makes no network request, and constraint 2 forbids one. In a downloaded copy that is a property of the code you are free to audit. Served from a host, the Content-Security-Policy in `nginx/conf/includes/headers.conf` makes it a property the browser enforces:

```
default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline';
img-src data:; connect-src 'none'; form-action 'none'; base-uri 'none';
frame-ancestors 'none'
```

`default-src 'none'` and `connect-src 'none'` mean the page cannot reach the network even if a future edit tried to. `img-src data:` covers the embedded logo and permits no remote image. `form-action 'none'` means the annotation form cannot navigate anywhere.

`'unsafe-inline'` is used rather than a script hash deliberately. A hash pins the exact bytes and breaks the page silently the moment `index.html` changes, which is the wrong failure mode for a records tool. The zero-network property this file exists to enforce comes from `default-src` and `connect-src`, and neither is weakened by that choice.

The configuration was tested against the real page before first deploy. Load, logo, inline style, inline script, a full inspection, annotation, attestation, clipboard delivery, and the theme toggle all work with the headers applied: zero CSP violations, zero page errors, and one HTTP request in total, the page itself.

## Layout

```
deploy/
  Staticfile                       root: public, location_include: includes/*.conf
  manifest.yml                     app name, route, 64M, staticfile buildpack
  prepare.py                       digest-guarded staging step
  nginx/conf/includes/headers.conf CSP and the other response headers
  public/                          generated by prepare.py, not tracked in git
```

`root:` must name a subdirectory. The buildpack honours `location_include` only when the document root differs from the app root, which is why `public/` exists rather than serving the repository root directly.

## Known failure modes

- **Route already taken.** Route names are unique across the whole platform. If `lineage.app.cloud.gov` is held by another org, `cf push` fails on the route and you need a different name in `manifest.yml`.
- **Memory.** 64M is enough for nginx serving one file. If the app crashes on start, raise `memory` in `manifest.yml` and push again.
- **No CSP header in the response.** Check that `Staticfile` still carries both `root: public` and `location_include: includes/*.conf`. Removing either one silently disables the header file.

## The hosted copy is not the defensible one

A downloaded file whose SHA-256 you verified is the artifact to use for anything going into a record. The hosted copy arrives over the network, so what you ran is whatever the host served at that moment. A `.gov` address makes that copy look more authoritative rather than less, which is why the digest guard exists and why the main README says the same thing.
